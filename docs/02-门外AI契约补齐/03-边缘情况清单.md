# 03 · 边缘情况清单

> 每条：**场景 → 期望 → 落点**。实现时逐条过一遍；漏一条就是一个"静默假死"。

## 一、设备与端口

| # | 场景 | 期望 | 落点 |
|:--:|:--|:--|:--|
| E1 | 板子拔掉，软件不关 | `devicePresent:false`、会话 `stale:true`；`readSince` 不报"没数据"，而是带 `state` | A-1/A-3 |
| E2 | 板子插回，COM 号变了 | `reopen` 用**原会话参数**重开：找得到同名端口就恢复；找不到 ⇒ `EDEVICE` 并提示"端口可能变了" | A-4 |
| E3 | 端口被别的程序占用 | `EALREADYOPEN` ＋ hint；⛔ 不无限重试 | A-5 |
| E4 | 自己的僵尸句柄（表里开着、实际已断） | `openPort` 自动恢复（`recovered:true`） | A-5 |
| E5 | 设备在、端口没开 | 读取命令 ⇒ `ENOPORT`；`receiveStatus` 仍能回 `devicePresent:true` | A-1 |

## 二、读取与游标

| # | 场景 | 期望 | 落点 |
|:--:|:--|:--|:--|
| E6 | 不传游标直接读 | `cursor-required` ＋ 当前 cursor；⛔ 不回放历史 | B-1 |
| E7 | 显式 `since:0` | 允许，回 `history:true` | B-1 |
| E8 | 软件 reload 后用旧游标读 | `cursor-ahead`（现有语义），带当前 `seq` | 现有 |
| E9 | 缓冲区滚出（读太慢） | 如实回 `lost`（条数），⛔ 不假装读全 | 现有 |
| E10 | `tail` 请求数 > 缓冲现有条数 | 有多少给多少 ＋ `lost` | B-2 |
| E11 | 过滤条件换了一个 | 不重复读同一批（cursor 按"检查过"前进） | B-3 |
| E12 | `since` + `tail` 同时给 | `EBADARGS` | B-1 |
| E13 | `limit` 超上限 | 按上限截断并回 `truncated:true`（⛔ 不静默截） | B-4 |

## 三、等待与并发

| # | 场景 | 期望 | 落点 |
|:--:|:--|:--|:--|
| E14 | `untilRegex` 超时 | `ok:true, timedOut:true`（**不是错误**） | C-3 |
| E15 | `untilRegex` 等待超过命令层超时 | 命令层先超时 ⇒ 客户端看到 `EPENDING`/`TIMEOUT`；meta 必须写明两者关系 | C-3 |
| E16 | 同一会话两个 `query` 同时发 | 第二个 `EBUSY`；⛔ 不排队 | C-4 |
| E17 | `query` 发出去但板子不回 | 等到 `timeoutMs` 后 `timedOut:true`，`lines` 里带回已收到的内容 | C-4 |
| E18 | `mark` 名字不存在 / 已被覆盖 | `ENOMARK` / 回执带 `previous` | C-1/C-2 |
| E19 | 等待期间设备被拔 | 立即结束等待：`ok:false, code:"EDEVICE"`（⛔ 不傻等到超时） | C-3/C-4 |
