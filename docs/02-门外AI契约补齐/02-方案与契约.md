# 02 · 方案与契约

> 本档定"做成什么样"。实现细节可调，**回执形状与语义不许悄悄改**——外部 AI 就是照这个用的。

## 〇、统一回执不变量（全组共用）

| 情形 | 形状 |
|:--|:--|
| 成功 | `{ ok: true, ... }` |
| 不成立 / 无操作（不是错误） | `{ ok: true, noop: true, reason: "<稳定字符串>", ... }`（沿用现有三态） |
| 失败 | `{ ok: false, code: "<E...>", message, hint? }` |
| 变更类 | 必须带后置状态（`value` / `previous` 或 `before` / `after`）——⛔ 禁 `{}` / `null` |
| 等待类 | 超时**是正常结局**：`{ ok: true, matched: false, timedOut: true, tookMs }` |

## 一、A 组 · 状态可信

### A-1 读取面固定随行 `state`

`receiveStatus` 与 `readSince` 的回执**每条会话**带：

```json
"state": { "paused": false, "portOpen": true, "devicePresent": true }
```

- 读不到的值给 `null`，**不猜**；
- `devicePresent` 用 `serial.listPorts()` 判断"名单里还有没有这个口"（插件可自己算，⛔ 不需要壳改）；
- `paused` 取自视图态：无视图 ⇒ `null`（不是 `false`）。

### A-2 `receiveStatus` 增三个时点

```json
{ "lastDataAt": 1730000000000, "idleMs": 4200, "devicePresent": true }
```

- `lastDataAt` = 最近一次收到数据的时刻（epoch ms）；从未收到 ⇒ `null`；
- `idleMs` = 距最近一次数据的毫秒数；无数据 ⇒ `null`。

### A-3 `listSessions` 增 `stale`

`stale = open === true && devicePresent === false`（"表里说开着，实际设备没了"）。

### A-4 新命令 `reopen`

```
serial-monitor.reopen { sessionId?, portName? }
→ { ok: true, sessionId, portName, recovered: true, tookMs }
```

- 语义：`closePort` → 等一小段 → `openPort`（同一会话、同参数）；
- 设备仍不在 ⇒ `{ ok:false, code:"EDEVICE", hint:"设备不在，检查 USB 连接" }`。

### A-5 `openPort` 遇「已被打开」

- 若**句柄是本插件自己的会话** 且 `devicePresent === true` ⇒ **自动走 A-4 重开**，回执带 `recovered: true`；
- 否则 ⇒ `{ ok:false, code:"EALREADYOPEN", hint:"该端口被其他程序占用" }`；
- ⛔ 不许再出现"报已被打开、但实际是自己的僵尸句柄"。

### A-6 暂停时被读

`readSince` 在 `paused === true` 时：**照常返回**（不空转），并带：

```json
{ "paused": true, "lostWhilePaused": <T0 结论> }
```

- T0 若确认"恢复后不回放" ⇒ `lostWhilePaused: true`（如实）；⛔ **不改成回放**（那会改缓冲语义，属拍板项）。

## 二、B① 组 · 一次读命令，三种取法（⛔ 不造第二条读路）

**只有 `serial-monitor.readSince` 一个读口**，靠参数选模式：

| 参数 | 含义 |
|:--|:--|
| `since: <seq>` | 从该游标往后读（原有） |
| `tail: <N>` | 读最近 N 条（新） |
| `afterMark: "<name>"` | 从命名游标之后读（新，见 C 组） |

三者**互斥**；都给 ⇒ `{ ok:false, code:"EBADARGS" }`。过滤器（正交，可叠加）：

| 参数 | 含义 |
|:--|:--|
| `prefix: "<s>"` | 只回以此开头的行为 |
| `grep: "<re>"` | 只回匹配正则的行（服务端过滤） |

### B-1 游标缺省不再有副作用

- **不传任何模式参数** ⇒ `{ ok:true, noop:true, reason:"cursor-required", cursor:<当前 seq> }`
  （**不再回放 200 行历史**）；
- **显式 `since: 0`** ⇒ 允许（=「我要整个缓冲」），回执带 `history: true`；
- 现有测试若依赖"缺省 0"行为，**同笔改测试**（这是有意变更）。

### B-2 `tail`

```
readSince { tail: 200 } → { ok:true, items:[…], cursor, count, history:true }
```

- `tail` 不受 `RECEIVE_READ_LIMIT_MAX` 限制（它就这么大），但**仍受缓冲容量**约束；
- 缓冲区不够 N 条 ⇒ 有多少给多少，并带 `lost`。

### B-3 过滤

- 过滤**不影响 cursor 前进**：cursor 仍等于最后一条**被检查过**的 seq，
  否则换个过滤条件会重复读到同一批；
- 回执带 `scanned: <检查条数>` 与 `matched: <命中条数>`，让人知道滤掉了多少。

### B-4 分页

- **不新增 offset**；分页就用 `cursor` 循环拉（已有契约）；
- `RECEIVE_READ_LIMIT_MAX` **保持 1000**（防回执撑爆）；要尾部用 `tail`，要大段用循环。

## 三、C 组 · 等待原语

### C-1 `mark`

```
serial-monitor.mark { name, sessionId? } → { ok:true, name, cursor, sessionId }
```

- 存在**插件内存**（运行期），reload 即失效；
- 同名覆盖，回执带 `previous` 旧游标；
- `cursor` 一并返回 ⇒ 调用方想自己存也行（不依赖插件内存）。

### C-2 `readSince --afterMark`

- 等价于 `since = marks[name]`；
- mark 不存在 ⇒ `{ ok:false, code:"ENOMARK", hint:"先 serial-monitor.mark {name}" }`。

### C-3 阻塞等行

```
readSince { untilRegex: "\\[SD\\] FatFs mounted", timeoutMs: 5000 }
→ 命中 { ok:true, matched:true, line, cursor, tookMs }
→ 超时 { ok:true, matched:false, timedOut:true, cursor, tookMs }
```

- **服务端阻塞**，客户端不用睡；
- `timeoutMs` 必填（⛔ 不设"无限等"默认值）；
- ⚠️ 命令层超时必须 **大于** `timeoutMs`（否则 CLI 先超时，看不到 `timedOut`）——两者关系写进 meta 描述。

### C-4 `query`（发+等，一次调用）

```
serial-monitor.query { send: "AT+RST\r\n", expect: "ready", timeoutMs: 5000, sessionId? }
→ { ok:true, matched:true, lines:[…], elapsedMs, cursor }
→ { ok:true, matched:false, timedOut:true, lines:[…], elapsedMs, cursor }
→ { ok:false, code:"ESENDFAIL" | "EBUSY" }
```

- 内部：记 cursor → `sendText` → 阻塞等 `expect` → 回命中的行；
- **同一会话并发 query ⇒ `EBUSY`**（⛔ 不排队，避免时序错乱）。

## 四、E 组 · 复位

```
serial-monitor.reset { method: "dtr"|"rts"|"both", holdMs?: 100, portName? }
→ { ok:true, portName, method, tookMs }
```

- 只调既有 `serial.setDtr` / `serial.setRts`（**零新 IPC**）；
- 序列：拉低 → 等 `holdMs` → 拉高；`both` = DTR 与 RTS 同相；
- 端口没开 ⇒ `{ ok:false, code:"ENOPORT" }`；
- ⚠️ meta 里写清：**这是电气复位，板子没接复位电路时不生效**（不是错误，是硬件事实）；
- ⛔ 不顺手加 `setDtr` / `setRts` 两条细粒度命令（不为假想消费者造面）。

## 五、错误码（插件侧先按这套写，与 04 S2 对齐）

| code | 何时 |
|:--|:--|
| `ENOSESSION` | 没有会话 / sessionId 找不到 |
| `ENOPORT` | 端口未打开 |
| `EDEVICE` | 设备不在（拔了） |
| `EALREADYOPEN` | 端口被占且不是自己能恢复的 |
| `ENOMARK` | 命名游标不存在 |
| `EBUSY` | 并发 query |
| `ESENDFAIL` | 发送失败 |
| `EBADARGS` | 模式参数互斥冲突 |

> `reason`（noop 三态）与 `code`（失败）**分工不同**：noop = "我没动，因为没必要"；code = "我做不到"。

## 六、明确不做

1. ⛔ 不做自动重连轮询（只在调用时检测设备在场）；
2. ⛔ 不做日志落盘（B②，需落点登记）；
3. ⛔ 不做编码自动识别（D2，壳侧）；
4. ⛔ 不做 direction（rx/tx）（壳侧 D1）；
5. ⛔ 不改 `seq` 全局单调语义、不改缓冲容量 2000；
6. ⛔ 不新增第二条读命令（`tail` / `afterMark` 都是 `readSince` 的参数）。
