# serial-monitor · 门外 AI 契约补齐

> **状态：📋 立案待实施（2026-11-17 复核）**。第一批目标版本 **1.0.37**（PATCH）。
> **来源**：两个真实工程的零知识外部 AI（`E:\lvgl_test` 的 01 / 02）——完全脱离壳仓、只拿到「MCP 复制这句话」与「CLI 复制这句话」，用 `linkdeskctl` ＋ MCP 做 LVGL 真机调试。
> **分档**：**05**（壳零改动；判据 = 动没动壳本体／产不产生壳发版需求）。⚠️ **翻档条件**：若 T0 确认「`closePort` 谎报已关闭／句柄仍被占」是壳侧缺陷，**该条**翻 04，其余组不受影响。
> **工作方式（用户 2026-11-12 定）**：**一次改、一次验、一次发**，⛔ 不按组拆成多个小版本。

## 一、案由（一句话）

外部 AI 用 CLI 调串口时，**看不见状态、读不全日志、等不到时序、复位只能靠重烧**。本批把这四件事补成"可信的仪器"。

## 二、两批外部 AI 怎么说（决定优先级）

| 议题 | 01 工程 | 02 工程 | 判定 |
|:--|:--|:--|:--|
| 状态可信 | paused 吞数据不回放 →「静默假死」 | 拔插 USB 后 `open:true` 撒谎、关不掉、EPENDING，绕 4~5 个来回 | **两批重合 ⇒ A 组最高优先** |
| 日志会丢 | 缺省游标回放 200 行历史 → 旧当新 | 刷屏冲掉启动段；上限 1000 取不到 8975 行尾部 | **两批重合 ⇒ B 组** |
| 等待 | 全靠 `sleep 9` 猜 | `send → 睡 → read` 有竞态 | **两批重合 ⇒ C 组** |
| 复位 | 为了重启板子走完整烧录（20+ 秒） | 未提（走 Keil+JLink） | 仅 01 ⇒ E 组 |
| 编码 | BOOT 段 GBK 乱码 | 同屏混编码 | **归 04 D2**（解码在壳，插件不可逆） |

## 三、第一批范围（A / B① / C / E）

| 组 | 补什么 | 一句话效果 |
|:--:|:--|:--|
| **A** | 设备在场 / 空闲时长 / stale / reopen / 暂停可见 | 拔插后一步恢复，状态不再撒谎 |
| **B①** | 游标缺省报警 · tail N · 前缀过滤 · 分页 | 刷屏也拿得到启动段 |
| **C** | mark · `--until-regex` · `--timeout` · `query` | 不用 sleep 猜时序 |
| **E** | `reset`（DTR/RTS） | 复位 20 秒 → 1 秒 |

**本批不做**：B② 日志落盘（需先登记落点）· D 编码"自动"档（等壳）· F 便捷项（capture 预设 / exportLog 路径）。

## 五、判据（做完怎么算成）

1. **拔插 USB 后一步恢复**，不再出现「已在打开 / 已关闭 / EPENDING」三连；
2. **刷屏之后** `tail 200` 仍能取到尾部，`prefix` 能筛出标记行；
3. **一条 `query`** 完成"发指令 + 等应答"，超时如实回报；
4. **`reset`** 让板子真复位，`tookMs < 1s`；
5. **无视图时**上述命令全部可用；
6. 单测齐、`verify` 九段绿、`build` 通过。
